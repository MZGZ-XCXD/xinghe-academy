# 数值平衡

## 一、时间尺度

| 概念 | 数值 |
| --- | --- |
| 1 真实秒（1× 速度） | 0.08 游戏日 |
| 1 游戏日 | 约 12 秒真实时间 |
| 1 游戏月（30 天） | 约 6 分钟真实时间 |
| 1 学年（360 天） | 约 72 分钟真实时间（5× 速度约 14 分钟） |

所有产出与消耗都以「每分钟」或「每天」定义，UI 展示时统一换算，因此调整时间尺度不会破坏平衡。

**单位约定（重要）**：数据表里的时长字段（`baseBuildMinutes`、`researchMinutes`、`durationMinutes`）内部按**游戏分钟**存，但界面**只用「游戏天数」显示时长**，现实时间放在括号里，例如「2.4 天（约 25 秒）」。1× 下 `1 现实秒 = 120 游戏分钟`，早期版本直接显示游戏分钟，让人误以为「显示 8 分钟却瞬间完成」——现在不会了。

## 二、开局基准（第 1 天）

| 项目 | 数值 |
| --- | --- |
| 资金 / 教学资源 / 声望 | 500 / 60 / 5 |
| 学生 | 高一 60、高二 40、高三 20（共 120） |
| 教师 | 15 人（八个学科组），平均教学能力约 45 |
| 已有建筑 | 教学楼 L1、食堂 L1、宿舍 L1、操场 L1 |
| 学校评级 | 约 31.6（普通高中） |
| 资金净产出 | 约 +0.75 / 分钟 ≈ 1 080 / 游戏日（学费 +0.87、食堂 +0.35、薪资 −0.44、维护 −0.03） |
| 教学资源净产出 | +0.55 / 分钟（教学楼 L1，未开课时） |
| 资金仓储上限 | 5 250（基础 5 000 + 食堂 L1 250）≈ 4.9 个游戏日的收入 |
| 教学资源仓储上限 | 950（基础 800 + 教学楼 L1 150） |

**节奏阶梯（教学楼，用初始收入衡量）**：L2 ≈ 2.3 个游戏日收入（1× 下约 28 秒）、L10 ≈ 25 个游戏日（约 5 分钟）、L25 ≈ 3 000 个游戏日。开局资金 500 买不起第一次升级，必须先运营两个多游戏日。

**事件频率**：平均 36 个游戏日一次（1× 速度下约 7.2 分钟现实时间），夏季事件更密集（-10% 间隔），校园安全 / 应急预案科技会进一步拉长间隔。

**剧情引导期间的节奏**：剧情引导期间不刷随机事件（只派发剧本事件「开学第一周」），玩家处理完第一件事件后随机事件恢复，所以开局不会被突发情况打断。学校被评为「待整改高中」起步；评级每次跨档都要通过一次考核（清单见 GAME_DESIGN），因此评级不再随数值自动飙升。

**现实时间速率**：资源速率统一按现实时间显示（1× 时 `1 现实分钟 ≈ 5 游戏日`）。开局资金约 +4.2K/现实分钟、教学资源约 +4.0K/现实分钟（1×）。数字看着大，是因为游戏时钟快（1 游戏日 ≈ 12 现实秒）；真正决定「能攒多少」的是仓储上限与造价。

**仓储提醒**：资源顶到上限时不再弹提示（避免刷屏），只在右栏资源面板显示「⚠ N 项接近上限」与一行说明；具体上限拆解在资源的悬浮明细里。想提醒得更明显，改 `RightPanel.vue` 的标签样式即可，不要在引擎里加通知。

## 三、核心公式

**建筑成本与工期**

```
成本(等级 n) = 基础成本 × costGrowth^(n-1) × build_cost加成
工期(等级 n) = 基础工期 × buildTimeGrowth^(n-1) ÷ build_speed加成
            ≈ 72 × sqrt(基础成本资金) × 1.12^(n-1) ÷ build_speed加成
产出(等级 n) = 基础产出 × n^1.2 × 对应资源加成
```

典型值：教学楼基础成本 1 800 资金 / 400 教学资源，`costGrowth = 1.35`，`baseBuildMinutes = 3 055`（1× 下约 25 秒）；第 2 级约 2 430 资金，第 10 级约 2.7 万，第 25 级约 327 万（`maxLevel = 40`）。

**两个节奏旋钮**

| 旋钮 | 位置 | 作用 |
| --- | --- | --- |
| 资源成本倍率 | `src/data/*` 里的 `baseCost` / `cost` | 决定「要攒多久」；建筑已按 ×10、科技 ×6、社团 ×4、活动 ×4、课程消耗 ×2.5 上调 |
| 成本增长曲线 | `costGrowth` | 决定后期是陡峭还是平缓；建筑当前为 1.32–1.41（早期版本是 1.5–1.65，后期过陡、前期过易） |

**工期与造价的关系**：工期不是独立拍的数，而是按 `1.2 × sqrt(造价资金)` 推导。小建筑 L2 约 25 秒、中型 40–60 秒、大型 1.5–3 分钟、顶级 6–16 分钟（均为 1× 速度）；`buildTimeGrowth` 统一为 1.12，避免后期工期失控。科技研究时间同理：`60 × sqrt(造价资金)`，限制在 0.4–15 游戏日（1× 下 5 秒 – 3 分钟）。

**课程结算**

```
有效容量 = 课程容量 + 60 × (教学楼等级 − 1)                 // 平行班
覆盖人数 = min(有效容量, 在校学生总数)                       // 每门课各自计算（并行，不是先到先得）
教师比例 = min(1.5, 学科教师数 / 课程需求)
有效成长 = 课程成长 × 学生成长加成 × 课程效率加成 × 教师效率 × 教师比例 × 覆盖比例 × 季节加成
教学消耗 = 每生每分钟消耗 × 1440 × 覆盖人数 × 课程消耗加成 × 天数
```

教学资源不足时课程仍然继续，但效果按 `0.4 + 0.6 × 可负担比例` 衰减，不会出现负资源或死锁。

**开局的教学资源压力**：120 名学生、教学楼 L1 时，教学资源产出约 792/游戏日。语文 + 数学两门课的全校覆盖消耗约 726/游戏日（刚好够，无衰减）；开到四门课约 1 382/游戏日（可负担率 0.57 → 效果 ×0.74）——这就是扩建图书馆 / 信息中心的动机。覆盖率不足时（学生多于平行班容量），成长与消耗都只按覆盖人数计算。

**学校评级**

```
评级 = 0.24×学术 + 0.14×体育 + 0.11×艺术 + 0.12×科研 + 0.06×品德 + 0.05×创造力 + 0.05×社交
     + 0.05×(100 − 平均压力) + 0.03×教师士气 + 0.15×基础设施(0-100) + 声望加成(≤ +12)
```

基础设施分 = `100 × Σ(建筑等级 × 类别权重) / (Σ + 70)`，类别权重在 0.85（生活）到 1.3（科研）之间。评级映射到 9 档评价：待整改 → 普通 → 区级示范 → 市级示范 → 省级重点 → 全国名校 → 国际知名实验校 → 世界实验标杆。

**比赛成功率**

```
实力 = 对应属性 × (0.7 + 教师效率 × 0.6) × 相关加成
成功率 = clamp(基础成功率 + (实力 − 难度) / max(20, 难度) × 0.55, 0.03, 0.97)
大成功概率 = 成功率 × 30%，奖励 ×1.75；失败奖励 ×0.25
```

**传承收益**

```
传承点 = floor( (评级 − 44)/3.4 + 毕业生/45 + 比赛胜利/9 + 累计科研/25000 + 已解锁成就×0.3 ) × 传承加成
```

条件：评级 ≥ 52、累计毕业生 ≥ 200、（首次）至少 1 次比赛胜利。

**传承节点成本** = `基础成本 × costGrowth^当前等级 × legacy_cost加成`，典型节点基础成本 2–14，`costGrowth` 1.5–2.0。

**离线**

```
计数时长 = min(离线秒数, 8 小时 × offline_efficiency加成)
等效游戏日 = 计数秒数 × 240 ÷ 1440 × 离线效率(默认 0.5%)，上限 20 个游戏日
```

## 四、流派互补（设计目标，不是补丁）

| 流派 | 优势 | 代价 |
| --- | --- | --- |
| 科研路线 | 科研点与科技解锁极快，后期建筑上限最高 | 资金与教学资源压力大，学生压力与教师负担高 |
| 体育路线 | 短期比赛收益高，满意度与健康好 | 占用课程槽与资源，学术增长受限 |
| 文化路线 | 声望与招生增长快，事件偏正面 | 直接现金流弱，前期基建慢 |
| 快乐校园 | 学生状态极佳，事件风险低 | 学术与竞赛效率明显下降 |
| 精英学校 | 顶分学生成长与考试极强 | 满意度与普通学生成长受损，教师压力上升 |
| 校友路线 | 毕业结算收益高，长期滚雪球 | 前期几乎无收益，需要长周期 |
| 国际路线 | 国际声誉与交流奖励高 | 需要大量前期投入与外语师资 |

## 五、调试与再平衡

- 平衡改动应只发生在 `src/data/*`（数值）与 `src/game/formulas/index.ts`（公式），不要改引擎流程。
- 可以用 `?debug=1` 的调试工具快速验证：`addAll` 注入资源、`advanceYear` 跳年、`setRating` 设定评级。
- 修改后必须运行 `npm test`：`tests/formulas.test.ts` 与 `tests/engine.test.ts` 会检查成本递增、产出递增、评级范围与数值合法性等基线。
- `tests/pacing.test.ts` 专门锁住节奏：时间换算、每栋建筑 L2 的现实施工时长（20 秒 ~ 30 分钟）、建造速度加成下的下限、升级攒钱时间的阶梯、科技研究时长范围。

## 六、当前已知的平衡问题（待校准）

1. **成本曲线已压平，但仍需真人数据**：`costGrowth` 从 1.5–1.65 降到 1.32–1.41，前期不再「点一下就买得起」，后期也不至于只能干等；不过评级 70 之后的收入增长仍可能跑在成本前面。
2. **学年节奏**：第一学年（1× 下约 72 分钟、5× 下约 14 分钟）对首次玩家偏长，后续版本可考虑「第一学年加速」开局选项。
3. **事件收益率**：单个事件的经济收益约为 1 天产出的 1–3 倍，长期看事件权重偏低。
4. **比赛与课程争抢学生**：目前比赛只校验学生总数，不真正占用学生，因此高级玩家可以同时开满课程与比赛。
5. **离线收益**：离线效率 1%、上限 20 个游戏日；8 小时离线约等于 20 个游戏日的产出，对长周期玩家可能偏少。
